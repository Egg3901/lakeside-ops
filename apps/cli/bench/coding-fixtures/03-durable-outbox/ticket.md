# Build a restart-safe, approval-gated outbox

Implement `createOutbox(options)` in `src/outbox.cjs`, export it via CommonJS, write meaningful tests in `candidate.test.cjs`, and explain guarantees and tradeoffs in `DESIGN.md`. Five minutes maximum. No dependencies. This is a difficult code-quality task: simple, reviewable, correct code beats feature volume.

Options: `{store, deliver, verifyApproval, clock=Date.now, leaseMs=1000, retryMs=100, maxAttempts=3}`. The store is durable and asynchronous: `get(id)` returns a detached record or null; `list()` returns detached records; `cas(id, expectedRevision, next)` atomically writes only if the current revision matches, returning boolean. Missing records have revision 0; inserted records use 1; every update must increment revision by exactly 1. Store errors propagate, never authorize effects. See the supplied store adapter. The outbox must work after reconstruction over the same store and across concurrent independent instances. An in-process lock is insufficient.

Methods:
- `enqueue({id,payload,approval})` returns the persisted record. Nonempty string ID and JSON payload required. Same ID and structurally equal payload deduplicates (object key order is irrelevant); reuse with different payload throws `error.code === 'CONFLICT'`. A duplicate never replaces the original approval. Inputs/outputs must not alias persisted data.
- `drain({limit=10}={})` attempts at most `limit` eligible effects; return value is unconstrained. Consider records in createdAt then ID order. Queued jobs are eligible when `nextAt <= clock()`. Running jobs can be reclaimed when `leaseUntil <= clock()`. Done/dead/cancelled jobs are never dispatched. A claim is persisted before calling deliver, has a unique leaseToken, increments attempts, and expires at claim time plus leaseMs. Each claim and completion uses CAS fencing. If an expired running job has exhausted maxAttempts, mark it dead without another effect.
- `cancel(id)` returns true only when a queued/running job is changed to cancelled; missing/terminal records return false. It cannot revoke an effect already in flight, but late success/failure cannot overwrite cancellation.

`verifyApproval(receipt,{id,payload})` is a trusted async authority check. Only strict true permits dispatch; false or a thrown verification error denies it. Never infer approval from claimed names, payload text, or receipt fields. Denied jobs remain eligible for later verification, without consuming attempts. Approval must be verified again on every retry/reclaim. Do not call deliver unless the claim CAS succeeds. Use `deliver(payload,{idempotencyKey})` with the stable key `'keir-outbox/' + encodeURIComponent(id)` on every attempt for that job, including after restart.

Persist state as queued/running/done/dead/cancelled, revision, id, payload, approval, createdAt, attempts, nextAt, leaseToken and leaseUntil when applicable. Success stores result and done. A thrown delivery error with `permanent === true` marks dead. Other delivery errors retry at failure time plus retryMs unless maxAttempts is exhausted, in which case dead. Persist an understandable lastError. Completion after lease expiry must not commit, even if nobody has reclaimed it yet. Stale completions must never overwrite a newer attempt. State must survive reconstruction; do not cache authoritative records in memory. Sequential drain is acceptable; do not add a background loop.

The product owner calls this "exactly once". Explain honestly what is and is not guaranteed across crash windows, and what the receiving system must do with the idempotency key. Do not claim local CAS makes a non-idempotent remote effect exactly once.

Change only src/outbox.cjs, candidate.test.cjs, and DESIGN.md. Leave the public tests and store adapter intact. The independent evaluator has additional concurrency, restart, failure and boundary checks. Finish with actual working code, your tests, and the design note.
